# PRO 6000 96GB：Min-SNR 配对试验加速配置

## 已做与未做

新增独立硬件协议 `configs/fold03_minsnr_pro6000.yaml`，原 batch32/FP16/5000 步协议不动，旧输出目录不动。本轮没有启动正式 017 训练，也未连接用户服务器。

本机 PyTorch 2.9.0+cu128 / RTX 5060 Ti 完成 53 项测试（31.83 秒），包括临时合成数据的小模型 BF16 CUDA 冒烟测试、CPU 流程、VAE 分块后验采样 RNG、测速失败处理及 A/B 输入匹配；这不是 PRO 6000 的速度或显存实测，更不是组织质量结果。PRO 6000 需要支持 Blackwell 的 CUDA/PyTorch 构建，建议核对 CUDA 12.8 或更新且兼容该 GPU 的发行版；不要仅凭 `torch.cuda.is_available()` 认定内核可用，真实测速会执行前向和反向。

## 参数与原理

- U-Net/成分编码器使用 BF16 混合精度。BF16 动态范围较大，适合支持该格式的 GPU；保留 FP32 参数/优化器状态与损失计算，不把整套模型强制转成 BF16。
- 关闭 gradient checkpointing，避免用重复前向节省显存；开启融合 AdamW 与 TF32。是否更快以服务器实测为准。
- 梯度累积仍为 1，patch 仍为 256，不加新增强或结构 loss，不改模型架构/采样协议。
- 冻结 VAE 保持 FP32，按 16 张一块编码，合并后验参数后一次性采样。避免完整大 batch 的 VAE 激活占满显存，也不改成后验 mode 或固定 latent 缓存。
- workers 默认 8，persistent workers 开启。确定性算法与 A/B 输入指纹检查保留，未为速度静默关闭配对控制。
- 静态起始建议 batch128、1250 步、LR1e-5、warmup25；**128 不是声称的 96GB 最优 batch**。推荐用下方测速选择，而不是手工把显存填满。

每组仍为 160000 个 patch 暴露量。测速候选 32/64/128/256/640/1000/1280，每档对 A、B 各做 3 步预热和 6 步计时，包括真实数据加载、FP32 VAE、反向、更新、EMA、日志和输入审计；不含初始化和检查点写盘。每档独立进程、从原始 raw50k 重启，不导出训练权重。只有明确 CUDA OOM 会被当作该档不可用；缺文件、内核不兼容、非有限梯度和 A/B 输入不匹配都立即报错，不被伪装为显存不足。

选择两组中较慢者吞吐最高、且 PyTorch 峰值 reserved 不超过“初始空闲显存减总显存的 8%”的 batch。报告记录 allocated/reserved、初始 free/total；不是承诺 `nvidia-smi` 恰好达到某个数字。留出约 7–8GB 余量用于导出、临时缓冲和波动，不分配无意义的占位张量。短测不是所有参数组合的全局最优证明；GPU 应独占，测试期间不要运行其他 GPU 作业。

**大 batch 不是纯粹的无损加速。** 同样 patch 暴露量下，优化更新次数变少，梯度噪声和学习动态改变；例如 batch640 对应 250 步，不能声称与原 batch32/5000 步完全等价。保持两组完全相同，因此本次 A/B 唯一差异仍是损失权重，但结论属于新的硬件协议。LR 不按 batch 线性放大，warmup/checkpoint 间隔按样本预算近似换算，原 LR/训练步数假设没有被验证为最优。主评价仍用最终 raw，不用 EMA 混比。

## 服务器命令

在已有服务器 Git checkout 的项目根目录，先进入实际 PyTorch 环境。检查工作树没有冲突再拉取；不使用强制覆盖：

```bash
git status --short
git pull --ff-only origin main
nvidia-smi
python -c "import torch; print(torch.__version__, torch.version.cuda); print(torch.cuda.get_device_name(0)); print('BF16:', torch.cuda.is_bf16_supported())"
```

数据清单、真实图片、VAE、raw50k U-Net 和同检查点编码器必须在服务器可访问。核对 `configs/sample_a_raw_id03_neighbors.yaml` 中模型路径及历史 hparams 中数据路径；GitHub 没有上传权重，不根据本机路径假定服务器文件齐全。

先仅执行硬件测速，不自动进入正式训练：

```bash
python -m scripts.tune_minsnr_throughput --config configs/fold03_minsnr_pro6000.yaml --output-dir performance/pro6000_tuning
```

看最终打印的 batch 和 `performance/pro6000_tuning/tuning_report.json`，逐档日志也在该目录。若只想快速比较三档，可加 `--batches 128 256 640`；需要更稳定计时可加 `--warmup-steps 5 --measure-steps 12`。若程序异常，先查看日志，不跳过错误直接训练。已存在的非空测速目录不会覆盖，重测请换新 `--output-dir`。

确认后依次执行，沿用测速生成的**同一份**协议：

```bash
python -m scripts.run_minsnr_ablation --config performance/pro6000_tuning/selected_protocol.yaml --phase prepare
python -m scripts.run_minsnr_ablation --config performance/pro6000_tuning/selected_protocol.yaml --phase train
python -m scripts.run_minsnr_ablation --config performance/pro6000_tuning/selected_protocol.yaml --phase evaluate
```

prepare 做严格权重/数据/配置检查和哈希锁定；train 依次训练 A、B；evaluate 才生成 raw50k/A/B 的同协议图和指标。不接着测速权重训练。正式结果根目录为 `08_训练与生成结果/05_Fold03_MinSNR_PRO6000/`，每合金对比图仍为 `evaluation/alloy_05/comparison_grid.png` 等。若已经准备过本硬件协议，请先在 YAML 选新的 `output_root` 再重新测速/prepare，不删除历史结果绕过保护。

不要把本机的 prepare/selected_protocol 文件直接用于服务器：它们含本机绝对路径。上面命令应在服务器本地生成。
